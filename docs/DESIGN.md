# Bamen 設計 (DESIGN)

設計の決定とその理由。節は足していく。決めるのはユーザーで、「案」と書いた節はまだ決まっていない。

## 1. 製品の大きな絵 (2026-11-23、ユーザーと決めた)

> 台本から動く絵コンテまでを、AI が書けるテキストで作る。カットが変わっても人物とセットは同じまま。カメラは座標ではなく撮影の言葉で書く。

Lily# が音、Shosa が人の動きを担うのに対し、Bamen (場面) は **撮影** を担う。セット、出演者、物、カメラ、カット、光、台詞をテキストで書く。コンパイラがカメラの位置を解き、映像の文法を検査する。プレビューは入力に合わせて再生される。

この構想に至るまでの検討 (推理シミュレータ、ガントチャート、家の 3D などとの比較) は `C:\MyProj\Ideas\` にある。

### 1.1 なぜ今か

- 動画生成 AI は **制御と一貫性** に弱い。カットが変わると人物やセットが変わり、カメラを正確に指示できず、1 カットだけを直すこともできない。
- 既存の AI プリビズの研究 (Mind-of-Director、StoryBlender、PrevizWhiz、いずれも 2026 年) は、複数のエージェントが中身の見えないシーンを組む方式。Blender MCP では、AI が Python で座標を書くのでカメラに苦戦している (利用者の報告)。StoryBlender の論文は「カット間の一貫性が、絵コンテとして使えるかをほぼ決める」と書く。
- Bamen の立ち位置は「**AI 動画に欠けている制御の層**」。正本は読めて、差分が取れ、検査できるテキスト。座標はコンパイラが撮影の語彙から解く (Shosa が「腕を上へ」から関節の角度を解くのと同じ)。
- 成り立つ条件が揃ったのは最近：AI が書き人が見て判断するという分担、標準の人型 (VRM) と glTF、ブラウザの 3D、素材の生成 AI、制御を求める中間の層 (YouTuber、インディーのゲーム、AI 動画の作り手)。
- 先行例：Prose Storyboard Language (Ronfard ら、2015 年、2022 年に改訂版) は 1 カットを 1 文で書く形式言語で、発想は同じだが、広く使われている実装は見当たらない。書く人がいなかったのが理由と見る (AI が書く今なら成り立つ)。
- 隣の製品：[shiwano/konte](https://github.com/shiwano/konte) (2026-06〜) は coding agent が生成 AI の動画制作 (ショットの計画、テイクの管理、時間つきの絵コンテ) を回すプラグイン。3D でカメラを解く方式ではない。比較の相手であり、連携の相手にもなりうる (Bamen の下絵を向こうの生成に渡す)。

### 1.2 誰が使うか

| 使い手 | 使い方 |
|---|---|
| 動画生成 AI で作品を作る人 | Bamen で構図とカメラと動きを決め、深度や骨格の下絵を動画生成 AI に渡して本番の絵にする |
| YouTuber、VTuber、MV を作る人 | Lily# の曲と Shosa の踊りにカット割りを付けて MP4 にする (Shosa の YouTube の計画と直結) |
| インディーのゲーム開発者 | カットシーンを書き、カメラ込みの glTF で Godot や Unity に持っていく |
| 自主制作の映画やアニメの作り手 | 台本から V コンテを作り、撮影の前にカット割りを詰める |
| AI エージェント | 文法を 1 本読んで書き、`check` と `sheet` で自分の出力を確かめる |

### 1.3 全体の構成

```
 入力                      Bamen                                  出力
 ─────                     ─────                                  ─────
 台本 (Fountain、任意) ─┐   .bamen  ──► 構文・束縛                 MP4 (字幕・曲つき)
 人の動き  .shosa ──────┤             │                          絵コンテのシート (PNG/PDF)
           .vrma .bvh ──┤             ▼                          glTF (カメラ・アニメつき)
           glb のアニメ ─┤   カメラの解決 (撮影の語彙 → 位置・画角)  編集用の EDL / OpenTimelineIO
 モデル    VRM / glTF ──┤             │                          動画生成 AI 向けの下絵
 セット    テキストの部屋┤             ▼                            (深度・骨格・線画・マスク)
           glTF の素材 ─┤   映像の文法の検査 (診断)
           360° の背景 ─┤             │
 音        .lys (Lily#) ┘             ▼
                           プレビュー (再生・シート・上からの配置図)
```

- **人の動きは Shosa に限らない**。`.vrma`、`.bvh`、glb のアニメ、動きの生成 AI の出力も受け取る。Shosa は「いちばん相性の良い供給元」。
- Shosa とは CLI とファイルでつなぐ。Shosa が Lily# の `lysc timeline` を読むのと同じ形で、Bamen は `shosa clip` (毎コマの関節) を読む。

### 1.4 言語の姿 (将来の姿の例。文法は §3 から段ごとに決める)

```
music "song.lys"
set 居間 { room 5x4 height 2.4; sofa at 1 0.5 facing south; window north; backdrop "dusk.hdr" }
cast 花子 "hanako.vrm" moves "hanako.shosa"
cast 太郎 "taro.vrm"   moves "taro.vrma"
prop 手紙 paper held 花子 right

scene 告白 in 居間 {
  shot 1 wide          2s       look 花子 太郎
  shot 2 medium        bars 5-6 over 太郎.shoulder look 花子.face
  shot 3 close  low    1.5s     look 花子.face  dolly in 0.5m
  shot 4 insert        1s       look 手紙
  say 花子 "ずっと渡せなかった。" at shot 3
}
```

- 書くのは **撮影の言葉**：ショットの大きさ (wide、medium、close、insert)、角度 (low、high、eye)、構図 (over-shoulder、two-shot)、動き (dolly、pan、tilt、orbit、follow)、見る先 (人の部位、物)。
- 座標はコンパイラが解く。人物の骨格 (毎コマの関節)、セットの壁、画角から位置を決める。数値で上書きもできる。

### 1.5 コンパイラが検査すること (診断)

- **180 度ルール**：会話の 2 人を結ぶ線を、カットの間でカメラが越えていないか
- **ジャンプカット**：前のカットとほとんど同じ構図ではないか
- **フレームアウト**：`look` の対象が枠から外れていないか (動きの途中も含めて)
- **遮蔽**：壁や家具や他の人物が対象を隠していないか。カメラが壁の中にないか
- **つながり**：前のカットの終わりと次の始まりで、人物の位置や持ち物が飛んでいないか
- **長さ**：拍や小節、台詞の長さとカットの長さが合っているか

### 1.6 プレビュー

- **再生**：カット割りどおりに再生する。エディタのカーソルの行のカットへ飛び、画面を押すとソースの行へ飛ぶ。
- **絵コンテのシート**：各カットの代表の 1 コマ、カット番号、長さ、台詞を並べる (`shosa sheet` の延長)。
- **上からの配置図**：カメラの位置と画角、人物の動きの線、180 度の線。
- **描き方**：灰色の仮の形を線画風、漫画風に描き、絵コンテとして魅力的に見せる。最終の絵は Bamen の役目ではない。

### 1.7 AI のループ

- `docs/GRAMMAR_FOR_LLM.md` を 1 本用意し、エージェントがこれだけで書けるようにする (Shosa の trials と同じ方法で測る)。
- VS Code の Copilot 向けのツール (`#bamenGrammar`、`#bamenCheck`、`#bamenSheet`) と、Claude Code 向けの MCP。
- 「3 カット目をローアングルに」で 1 行だけ書き換わり、前後の比較がシートで見られる。

### 1.8 しないこと

- 最終の映像の描画 (動画生成 AI、Blender、ゲームエンジンに任せる)
- 一般的な 3D モデリング (素材は読むだけ)
- 人の動きの作成 (Shosa や外部の素材に任せる)

### 1.9 危うさ

- **範囲が広がりやすい**：§1.8 を守る。段ごとに動画で見せられるものを門にする。
- **カメラの解決の質**：価値はほぼここで決まる。M1 で、人が手で置いたカメラと見比べる試行をする。
- **素材のライセンス**：VRM や glTF の素材は利用条件がまちまち。サンプルは自前か CC0 に限る。
- **競合の速さ**：研究も製品も 2026 年に増えている。M1 と M2 を早く動画で示す。

## 2. リポジトリと名前 (2026-11-23、ユーザー決定)

- **Shosa とは別のリポジトリ、別の言語** (`C:\MyProj\Bamen`)。理由：拍で書く踊りの文法と、秒とカットで書く撮影の文法は性質が違い、混ぜると両方の文法が重くなる。人の動きの供給元を Shosa に限らない。Shosa は「ゲームのための人の動き」に絞ったまま保つ。Lily# → Shosa と同じく CLI とファイルでつなげば境目が細い。
- Shosa のプレビューのカメラ (Shosa DESIGN.md 119 の Fit とスライダー) は UI のまま残し、言語としてのカメラは Bamen に置く。
- 拡張の基盤 (言語サーバー、プレビュー、MP4 の書き出し、VRM の読み込み) は最初は Shosa から写し、2 つ目の写しが要る時点で共通の部品に切り出す。
- **名前は Bamen (場面)**。Konte は shiwano/konte と重なる (§1.1)。Bamen は GitHub に同名がなく、npm、NuGet、VS Code Marketplace も空き、Web 検索もほぼ空 (2026-11-23 に調べた)。商標 (J-PlatPat、USPTO) は未確認で、公開の前に確かめる。拡張子は `.bamen` (案)。

## 3. M0 の文法 (案。決めるのはユーザー。実装していない)

M0 の目標：**Shosa の踊り 1 本を、固定カメラの 3 カットで撮って再生し、絵コンテのシートを出す**。カメラの動き (dolly、orbit) は M1。

### 3.1 見本

```
// Shosa の samples\dance.shosa (3 人、song.lys の Verse と Chorus) を 3 カットで撮る
title "Dance in three shots"
dance "dance.shosa"                     // 踊り手、動き、曲 (music "song.lys") をそのまま持ってくる

shot 1 wide   eye   bars 1-4   look alice bob carol
shot 2 medium low   bars 5-6   look alice
shot 3 close        bars 7-8   look alice.face
```

### 3.2 決める点 (それぞれ第 1 案と、その代わり)

| # | 点 | 第 1 案 | 代わり |
|---|---|---|---|
| 1 | 動きの持ち込み方 | `dance "x.shosa"`：Shosa の譜をまるごと。踊り手の名前と立ち位置と曲も付いてくる | `cast 名前 "model.vrm" moves "x.shosa" dancer alice`：1 人ずつ。M3 の会話の場面ではこちらが要る |
| 2 | 時間の単位 | 曲があれば `bars 1-4` (小節)、`beats` も。なければ `2s` (秒) | 秒だけ (曲の小節は CLI が秒に直して見せる) |
| 3 | カットの長さ | 各 `shot` に書く。隙間や重なりは診断 | 次の `shot` が来るまで続く (最後だけ長さを書く) |
| 4 | ショットの大きさの意味 | 対象の背丈に対する枠の高さ。`wide` は全身と周り、`medium` は腰から上、`close` は肩から上 (対象が顔なら顔) | 焦点距離 (mm) で書く |
| 5 | 対象が動くとき | カットの間の対象の動きをすべて含む一番近い位置に固定 (フレームアウトしない) | カットの始めのコマで合わせる (はみ出したら診断) |
| 6 | カメラの向き (どちら側から撮るか) | 既定は対象の正面寄り。`from left` `from back` などで選ぶ | 必ず書く |
| 7 | 拡張子 | `.bamen` | `.scene` (汎用すぎて衝突する) |

### 3.3 M0 の実装の形 (案)

- .NET 10 (Shosa と同じ)：`Bamen.Core` (構文、束縛、カメラの解決、診断)、`Bamen.Cli` (`bamen check`、`bamen sheet`、`bamen cameras` = 解いたカメラの JSON)、`Bamen.Lsp`、`Bamen.Tests`、`editors/vscode`。
- 動きは `shosa clip` の JSON (毎コマの関節) を読む。`shosa` は `BAMEN_SHOSA` → PATH → VS Code の Shosa 拡張の順に探す (Shosa が `lysc` を探すのと同じ形)。
- プレビューは Shosa のプレビュー (three.js、three-vrm) を写し、カメラを Bamen が解いたものに差し替え、カットで切り替える。MP4 の書き出しも写す。
